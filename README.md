# BotKit — основа для собственного Telegram-бота

**Принимает текст, сохраняет задачу, запускает ваш обработчик и выдаёт результат по команде.** Очередь, статусы, повтор после ошибки и настройки доступа уже готовы. Логику своего бота вы пишете в `task.py` самостоятельно или с помощью ИИ.

Встроенный пример превращает строки в чек-лист. Полный цикл работает локально без Telegram, ключей и внешних сервисов.

```text
Сообщение → очередь SQLite → ваш task.py → сохранённый результат
                 ↑                              ↓
             /retry                         /status
```

## Попробовать за минуту

Нужен Python 3.11 или новее. В PowerShell из папки репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m botkit example
```

На macOS/Linux замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`. Установка может потребовать сеть для сборочных зависимостей; сам пример работает без сети.

Команда создаёт временного бота, принимает сообщение через подменённый Telegram-транспорт, сохраняет задачу в настоящую SQLite, обрабатывает её и читает результат через `/status`:

```text
Чек-лист:
☐ Сформулировать задачу
☐ Проверить результат
☐ Записать выводы
```

После примера временные файлы удаляются. Это полный локальный цикл; живое подключение к Telegram отдельно не проверено.

## Создать своего бота

```powershell
.\.venv\Scripts\python.exe -m botkit new mybot --dest .
```

Получится папка:

```text
mybot/
  bot.toml       — приветствие, запасной ответ и разрешённые пользователи
  plugin.py      — команды и постановка задач в очередь
  task.py        — ваша логика обработки
  .env.example   — образец настройки токена
  .gitignore
  README.md
```

В `task.py` замените метод `Plugin.on_text(message)`. На входе есть текст, ID чата, пользователя и обновления; на выходе — непустая строка до 4096 символов. Для интеграции подключите собственный клиент и зависимости в своём окружении. Произвольный код обработчика исполняется с правами процесса, в том числе в локальном демо.

Для синхронного бота: `botkit new simple --template echo`. Он отвечает через `plugin.py` сразу, без очереди. По умолчанию CLI создаёт шаблон `tasks`.

### Проверить свой обработчик без Telegram

```powershell
.\.venv\Scripts\python.exe -m botkit demo --config .\mybot\bot.toml --text "Подготовить документ"
.\.venv\Scripts\python.exe -m botkit worker --config .\mybot\bot.toml --once
```

Первая команда выведет номер задачи. Подставьте его:

```powershell
.\.venv\Scripts\python.exe -m botkit demo --config .\mybot\bot.toml --text "/status НОМЕР_ЗАДАЧИ"
```

Демо использует вымышленные ID пользователя и чата `1`. Если настроен список доступа, разрешите этот ID в демопапке. Создавайте отдельные папки для демо и реальной работы: задания демо сохраняются в очереди выбранной папки.

### Подключить Telegram

1. Создайте своего бота через BotFather. Скопируйте `.env.example` в `.env` внутри `mybot` и укажите свой токен. Не публикуйте его.
2. При необходимости в `bot.toml` заполните `allowed_users = [...]` собственными числовыми Telegram ID. Пустой список разрешает доступ всем. Шаблон задач работает только в личных чатах.
3. Запустите приём сообщений:

```powershell
.\.venv\Scripts\python.exe -m botkit run --config .\mybot\bot.toml
```

4. Во втором терминале запустите обработчик очереди:

```powershell
.\.venv\Scripts\python.exe -m botkit worker --config .\mybot\bot.toml
```

Процессы работают до Ctrl+C. Нужен включённый компьютер и доступ к Telegram. Для long polling отключите webhook у этого бота; сервер и автостарт не включены. На одну папку и токен запускайте один процесс `run`. При смене токена используйте новую папку, чтобы не смешивать позиции обновлений.

## Что уже есть

| Функция | Поведение |
| --- | --- |
| Постоянная очередь | SQLite хранит текст задания, владельца, результат и статус после перезапуска |
| Отдельный обработчик | Медленная задача выполняется в worker, приём сообщений продолжается |
| Защита от повторов | Повтор Telegram update не создаёт вторую задачу; новое сообщение с тем же текстом создаёт новую |
| Статусы | `/status <номер>` показывает состояние или результат только владельцу задачи |
| Повтор и отмена | `/retry <номер>` повторяет неудачную задачу; `/cancel <номер>` отменяет ещё не взятую в работу |
| Ограничение очереди | До 20 незавершённых задач на пользователя в личном чате |
| Контроль доступа | Необязательный список пользователей проверяется до вызова обработчика |
| Позиция Telegram | После успешного ответа сохраняется в SQLite |
| Обработка ошибок | Ошибка или слишком длинный ответ обработчика не раскрывают текст исключения пользователю |
| Смена логики | `task.py` для очереди, `plugin.py` для синхронного бота |

## Границы и эксплуатация

- Результаты читаются командой `/status`; worker не отправляет сообщения самостоятельно.
- Поддерживаются текстовые сообщения и обычные текстовые ответы. LLM, платежи, веб-панель, вложения и хостинг не входят в пакет.
- Встроенный пример форматирует чек-лист. Для вашей задачи нужен свой обработчик.
- При аварии между отправкой ответа Telegram и сохранением позиции возможен повтор ответа. Постановка задачи защищена от такого повтора, но гарантий «ровно один раз» для внешних действий обработчика нет. Используйте `message.update_id` как ключ идемпотентности при интеграции.
- Несколько workers атомарно забирают разные задания. Один worker выполняет задачи последовательно; таймауты внешних запросов задаются внутри вашего обработчика.
- После аварии worker задания `running` сохраняют статус. Остановите **все** workers, затем выполните `botkit recover --config mybot/bot.toml`. Прерванные задачи вернутся в очередь; уже выполненные внешние действия могут повториться.
- `data/` содержит ID, тексты и результаты в незашифрованной SQLite и исключена из Git. Автоматической очистки завершённых задач нет; срок хранения и резервные копии определяет владелец. Храните папку локально с подходящими правами доступа.
- Пример и тесты работают локально. Живой Telegram, нагрузка и непрерывная работа сервиса здесь не подтверждены.
- Установка `pip install -e .` привязана к папке исходников. Созданная папка бота требует установленного BotKit; для переноса установите пакет в новом окружении.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются полный цикл задачи, повтор обновления, чужой доступ, сбой отправки, перезапуск, конкурирующие workers, отмена, лимит очереди и ошибки обработчика. Telegram подменён локальным транспортом.
